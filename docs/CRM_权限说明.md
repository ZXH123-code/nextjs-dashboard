# CRM 权限说明

## 数据库迁移

新增 `role` 字段后需执行：

```bash
npx prisma db push
```

或

```bash
npx prisma migrate dev --name add_user_role
```

## 角色

| 角色 | role 值 | 可见范围 |
|------|---------|----------|
| 销售总管 | `admin` | 所有线索、商机、客户、跟进记录 |
| 销售人员 | `sales` | 仅自己负责的（salesPersonId = 自己） |

> 说明：`role` 字段存储在 `users` 表中，登录后会通过 NextAuth 的回调从数据库读取最新值，
> 因此在「权限管理」页面修改角色后，**几乎实时生效**，无需用户退出重登。

## 如何设置销售总管

### 方式一：权限管理页面（推荐）

1. 使用已有销售总管账号登录
2. 侧边栏点击 **权限管理**（仅 admin 可见）
3. 在用户列表中，将目标用户的角色改为「销售总管」
4. **权限变更立即生效**，无需重新登录

若系统中尚无销售总管，需先用方式二在数据库中设置第一个 admin。

### 方式二：直接改数据库（首次设置）

在数据库中将对应用户的 `role` 设为 `admin`：

```sql
UPDATE users SET role = 'admin' WHERE email = '管理员邮箱@xxx.com';
```

或使用 Prisma Studio：

```bash
npx prisma studio
```

在 `users` 表中找到对应用户，将 `role` 字段改为 `admin`。

**默认**：新注册用户 `role` 为 `sales`。

## 数据过滤规则

- **线索 / 商机 / 客户**：销售人员只看 `salesPersonId` = 自己的记录
- **跟进记录**：销售人员只看以下三种之一：
  - 自己跟进的（`follow_up_by_id` = 自己）
  - 关联客户是自己负责的
  - 关联商机是自己负责的

技术实现上，所有 CRM 列表查询都通过 `app/lib/crm.ts` 中的帮助函数注入过滤条件：

- 未登录：返回一个永远查不到数据的条件
- `admin`：不加额外 where（查看全部）
- `sales`：自动追加 `salesPersonId = 当前用户` 等约束

## 新建时的负责人

- 销售人员新建线索、商机、客户时，会自动将 `salesPersonId` 设为当前用户
- 销售总管新建时，`salesPersonId` 可为空（需在表单中支持选择负责人，当前版本未实现）

## 线索管理表：新建、导入、销售人员与表格编辑

- **新建线索**：仅管理员可点击「新建线索」，会新建一条空记录（客户名称「（待补全）」），在表格内行内编辑补全。销售人员可见该按钮，点击后弹出**友好权限提示框**（仅管理员可新建线索，如需使用请联系管理员），不使用 alert。
- **批量导入**：仅管理员可点击「批量导入」并完成导入。销售人员点击后弹出**友好权限提示框**（仅管理员可批量导入线索）。
- **邮件通知**：仅管理员可发送线索分配变更的邮件通知。销售人员点击「邮件通知」后弹出**友好权限提示框**（仅管理员可发送邮件通知）。
- **销售人员**：仅管理员可指定/变更线索的销售人员（下拉选择）；销售人员该列为**只读**，仅显示当前负责人姓名。
- **表格内编辑**：仅管理员可点击线索行的单元格（客户名称、昵称、城市、行业、线索来源）进行行内编辑；销售人员该列为只读。
- **删除**：仅管理员可删除线索。管理员可**强制删除任意线索**，系统会**级联删除**该线索关联的商机及该商机下的客户（跟进记录保留但解除关联）。每条线索对管理员都显示「删除」按钮。

## 商机管理表：无独立新建入口

- 商机仅由「线索状态改为有意向」时**自动生成**，无「新建商机」页面。
- 补全商机在**商机表内行内编辑**（点击单元格即可），或从线索表点「编辑/补全商机」跳转商机表并高亮该条。

## 客户管理表：行内编辑与权限

- **表格内编辑**：客户名称、昵称、城市、客户分层、行业、初次维护日期支持 **Excel 风格行内编辑**。**管理员**可编辑全部客户；**销售人员**仅可编辑自己负责的客户（`salesPersonId` 为自己的记录）。
- 客户表已**无「跟进记录」按钮**，通过展开该行查看「跟进时间线」即可查看该客户的跟进记录；全部跟进汇总在「跟进记录」页面。

## 无权限时的提示方式

- 新建线索、批量导入、邮件通知、分配销售人员失败等**无权限或操作失败**时，统一使用 **PermissionDeniedDialog** 组件（`app/dashboard/crm/components/PermissionDeniedDialog.tsx`）弹窗提示，带图标与「知道了」按钮，不再使用浏览器 `alert()`。
