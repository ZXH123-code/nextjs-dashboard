# CRM 线索批量导入功能说明

> 功能：通过上传 Excel（.xlsx）文件，将多条线索一次性导入到「线索管理表」中，仅 **管理员（admin）** 可用。

---

## 一、入口与使用场景

- **入口页面**：`仪表盘 → CRM → 线索管理表`（`/dashboard/crm/leads`）
- 当当前登录用户角色为 **admin** 时，右上角会看到两个按钮：
  - `新建线索`
  - `批量导入`
- 点击 **`批量导入`** 进入导入页面：`/dashboard/crm/leads/import`

**适用场景：**

- 从第三方渠道（飞书表格、活动报名、名单公司等）导出的线索名单
- 一次性同步历史线索数据

---

## 二、Excel 模板字段定义

系统目前只读取 **第一张工作表**，并将 **第一行视为表头**。支持的中文表头如下：

| 列名（表头） | 是否必填 | 说明 |
| ------------ | -------- | ---- |
| 客户名称     | 是       | 对应 `crm_leads.customer_name`，为空的行会被判定为错误并跳过 |
| 昵称         | 否       | 对应 `nickname` |
| 城市         | 否       | 对应 `city` |
| 详细地址     | 否       | 对应 `address` |
| 行业         | 否       | 对应 `industry` |
| 线索来源     | 否       | 对应 `lead_source`，如「展会」「官网」「转介绍」等 |
| 客户分层     | 否       | 对应 `customer_tier`，如「A/B/C」分层 |
| 销售人员邮箱 | 否       | 用于匹配 `users.email`，匹配成功后写入 `sales_person_id` |
| 状态         | 否       | 线索状态，支持：`未跟进` / `跟进中` / `有意向` / `无意向`，为空时默认 `未跟进` |

> 注意：
>
> - 列名必须为 **以上中文字段**，否则该列会被忽略。
> - 允许只填写部分列，例如只填「客户名称 + 城市 + 销售人员邮箱」。

## 三、导入行为与校验规则

### 1. 权限与文件校验

- **权限**：仅 `role = "admin"` 的用户可以访问导入页面和调用导入接口，否则会被重定向或返回 403。
- **文件格式**：
  - 仅支持 **`.xlsx`**（Excel 2007+）格式
  - 若上传其他格式，将提示「目前仅支持 .xlsx 格式」
- **文件大小**：
  - 默认限制为 **5MB**，超过会提示「文件过大，请控制在 5MB 以内」

### 2. 行级校验逻辑

对每一行（从第 2 行开始）做如下检查，若不通过则记录为错误并跳过该行：

1. **客户名称**
   - 为空：记录错误「客户名称为空」
2. **状态**
   - 允许值：`未跟进` / `跟进中` / `有意向` / `无意向`
   - 为空：自动使用默认值 `未跟进`
   - 其他值：记录错误「状态不合法：xxx，仅支持 未跟进/跟进中/有意向/无意向」
3. **销售人员邮箱**
   - 若填了邮箱，会先收集全表中所有不为空的邮箱，然后一次性查询 `users` 表：
     - `select id, email from users where email in (...)`
   - 某行的邮箱在 `users.email` 中找不到：记录错误「销售人员邮箱在系统中不存在：xxx」
   - 找到时：将该用户的 `id` 写入 `salesPersonId`

其他字段（昵称、城市、详细地址、行业、线索来源、客户分层）：

- 若单元格为空，写入时对应字段为 `null/undefined`
- 若有值，直接按字符串写入

### 3. 写入策略

- 对通过校验的行构造数据数组，调用：
  - `prisma.crm_lead.createMany({ data: dataToInsert })`
- `created_at` 由数据库默认值自动填充
- 若整个文件中 **所有行都存在问题**，不会写入任何数据，并返回「没有可导入的数据，请检查表格格式和内容」

## 四、导入结果与错误展示

后端导入接口返回结构（简化）：

```ts
{
  success?: boolean;
  inserted?: number; // 成功写入的条数
  failed?: number;   // 失败的条数
  error?: string;    // 全局错误信息
  errors?: { row: number; message: string }[]; // 每一行的错误详情
}
```

前端在导入页面会做友好的提示：

- **导入成功**（无全局错误）：
  - 显示绿色提示：「导入成功 X 条，失败 Y 条」
  - 若 `errors` 不为空，会列出前 5 条错误，例如：
    - 「第 3 行：客户名称为空」
    - 「第 5 行：状态不合法：xxx」
    - 「第 8 行：销售人员邮箱在系统中不存在：aaa@bbb.com」
  - 其余错误只显示总数，例如「…… 共 N 条错误，仅展示前 5 条」
- **导入失败**（发生全局错误，如文件格式问题）：
  - 显示红色错误块，提示具体原因：
    - 「请上传 Excel 文件」
    - 「目前仅支持 .xlsx 格式」
    - 「文件过大，请控制在 5MB 以内」
    - 「表格内容为空」
    - 「解析或导入 Excel 失败，请检查文件格式」

导入成功后，前端会调用 `router.refresh()`，刷新当前页面数据，回到线索列表即可看到新增的线索。

## 五、典型操作流程示例

1. **准备 Excel 模板**
   - 在 Excel 中新增一个工作表，在第一行填写表头，例如：
     - `客户名称`、`城市`、`行业`、`线索来源`、`销售人员邮箱`、`状态`
   - 从第二行起填入多条线索记录
2. **登录系统**
   - 使用管理员账号登录（admin 角色）
3. **进入导入页面**
   - 打开「线索管理表」  
   - 右上角点击「批量导入」
4. **上传文件**
   - 将 `.xlsx` 文件拖入上传区域，或点击选择文件
   - 点击「开始导入」
5. **查看结果**
   - 根据提示确认成功导入的条数和错误行
   - 若有错误，根据错误信息回到 Excel 修正，再次上传

## 六、注意事项与扩展

- **销售人员邮箱匹配**
  - 建议提前确认系统中的 `users.email` 与 Excel 中的「销售人员邮箱」一致
  - 常见问题是 Excel 中多了空格或大小写不一致，建议统一为小写并去除空格
- **重复数据的处理**
  - 当前版本 **不会做去重检查**，同一客户可以被多次导入为多条线索
  - 后续如需「按客户名称 + 城市」等规则去重，可以在导入逻辑中增加唯一性校验
- **大文件导入**
  - 若单次导入的行数很多（几万行以上），建议拆分文件，每次控制在几千行以内，以避免浏览器或服务器处理时间过长

如需定制更多导入规则（例如：自动根据手机号去重、自动关联已有客户等），可以在 `app/api/crm/leads/import/route.ts` 中扩展相应逻辑。
